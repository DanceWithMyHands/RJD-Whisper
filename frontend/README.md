# РЖД · Протокол — Frontend

Интерфейс системы автоматического документирования совещаний РЖД.
**React + TypeScript + Material UI (Vite)**, данные — из реального API бэкенда
(**TanStack Query + axios**), JWT-аутентификация, ролевая модель доступа.
Моковых данных и заглушек нет.

## Запуск

Нужен запущенный бэкенд (по умолчанию `http://localhost:8000`, см. `../backend`).

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173 и войдите: `admin@rzd.ru` / `admin12345`.
Запросы идут на `/api/v1` и проксируются Vite на `http://localhost:8000`.
В продакшене базовый URL задаётся переменной `VITE_API_BASE_URL`.

## Экраны

| Экран | Маршрут | Источник данных |
|-------|---------|-----------------|
| Вход | `/login` | `POST /auth/login` |
| Дашборд | `/` | список совещаний + детально активное |
| Новое совещание | `/connect` | `POST /meetings`, `connect-bot`, согласие |
| Запись | `/recording` | `recording/start` · `recording/stop` |
| Транскрипт | `/transcript` | детали совещания (реплики, говорящие) |
| Поручения | `/assignments` | CRUD, `bulk/confirm`, `bulk/send`, экспорт |
| Архив | `/archive` | список совещаний |
| Пользователи | `/users` | справочник учёток, создание с ролью, поручения по сотруднику (admin) |

## Роли и доступ

- **admin** — полный доступ, управление пользователями (экран «Пользователи»).
- **manager / deputy** — создают совещания и поручения, рассылают, видят все данные.
- **employee** — только просмотр совещаний, где он участник, и своих поручений; управляющие пункты скрыты.

Участников совещания можно выбрать только из справочника пользователей (учётки заводит администратор). Бэкенд дополнительно проверяет права на каждом эндпоинте.

## Архитектура

```
src/
  api/         axios-клиент (JWT + refresh), типы, функции эндпоинтов
  auth/        AuthContext, экран входа, защита маршрутов
  hooks/       React Query: запросы и мутации
  store/       контекст активного совещания (persist в localStorage)
  components/  Layout, диалоги, чипы, состояния загрузки/ошибок
  pages/       экраны
```

## Поведение

- Все маршруты, кроме `/login`, защищены: без токена — редирект на вход.
- Токен в localStorage; при 401 обновляется по refresh-токену, иначе — выход.
- «Активное совещание» выбирается в архиве/дашборде и используется экранами записи, транскрипта и поручений.
- Запись: кнопки start/stop дёргают реальные эндпоинты; таймер и волны — визуальная индикация.
